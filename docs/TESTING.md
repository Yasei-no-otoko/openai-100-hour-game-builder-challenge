# 検証結果 / v0.2.0

## 実行環境と方法

Linux上のNode.js 22.16.0とChromium 144.0.7559.96、Python Playwrightを使用しました。ゲームの配布HTMLをそのままメモリに読み込み、最初からネットワークを無効にして検証しています。タッチ試験はChromiumのCDPを通してマルチタッチ入力を発行し、移動とアクションのポインターIDを観測しました。

ファイルURLでの直開き、物理的なiPhone / Android、Safariは未検証です。WebKit用ブラウザーの追加取得はDNSエラーにより失敗しました。60fps達成、実機メモリー使用量、発熱、長時間安定性の保証はしていません。

## 縦画面のケース

320×568、375×667、390×844、393×852、430×932、360×800（CSS px）で、タイトル→出撃設定→契約選択→戦闘→停止→ヘルプ→設定→左利き反転→リザルト→リトライを確認しました。393×852と430×932では上47px・下34pxのセーフエリアをCSS変数で模擬しています。実際のOSのセーフエリアやSafariのツールバーを再現した実機試験ではありません。

主要なアクティブ操作について、44px以上のヒット領域と画面内配置を検査しました。契約の確定ボタン、移動パッド、反射、ダッシュ、ノヴァ、一時停止が対象です。縦スクロールで到達する画面のボタンは、スクロールした状態で検査しています。

## マルチタッチ・ライフサイクル

移動中に別の指で反射、反射の指だけを離して移動継続、移動中にダッシュ、長押しで勝手にダッシュが繰り返されないこと、移動指の解放とpointercancel、戦場上での相対ドラッグ、ノヴァ発動を確認しました。

向き変更時には停止し、入力状態を解除。世界の寸法を変えず、停止中の時間が進まないことを確認しました。フォーカス喪失とテストから発行したvisibilitychangeでも停止します。実際の着信・ロック・OSアプリ切替は未検証です。

カードのスクロール操作だけでは選択・戦闘開始が発生せず、カードをタップしても確認ボタンを押すまで戦闘を開始しません。契約破棄のキャンセルでは状態が変わらず、確定時にのみ破棄されることを確認しました。
