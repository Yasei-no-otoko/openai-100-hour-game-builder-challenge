# モバイルUI/UX実装 / v0.2.0

## インタラクション

右手の親指側に反射・ダッシュ・ノヴァ、左手側に移動パッドを配置します。自動照準と自動射撃を有効にし、移動と弾幕への対処に操作を集中させます。左利き設定では左右のDOM配置を反転します。感度は70〜140%で調整可能です。

移動は接触開始点からの相対ドラッグです。機体を接触位置に瞬間移動させません。移動パッドと戦場のどちらでも同じ方式を使用します。後から加わった移動用の指で先行する指の所有権を奪いません。

`TouchController` は移動ポインターIDとアクションポインターのマップを別々に管理します。`setPointerCapture()`、`pointerup`、`pointercancel`、`lostpointercapture` を用い、反射側の指を離した時に移動まで解除する不具合を避けます。アクションは次の物理ステップが実行されるまで保持し、その後1回だけ消費します。長押し自動連打はしません。

キャンバス・移動パッド・アクションボタンに `touch-action: none` を限定します。メニューや選択肢は `pan-y pinch-zoom` と独立したスクロールコンテナーで縦スクロールできます。スクロール操作が契約確定にならないよう、カードの選択と実行を分けています。

契約破棄とラン終了は一時停止中の確認画面を経由します。破棄の確認中はゲーム内の時間が進みません。破棄をキャンセルしても契約・HP・敵弾を変更しません。

## レイアウト

coarse pointer、タッチポイントあり、または幅760px未満の場合にタッチUIを選びます。UIは物理CSSピクセルのまま再配置し、デスクトップ用の1280×800 UI全体を縮小しません。アクティブな主要操作のタップ領域は44CSS px以上です。

`100dvh` を使い、対応していない場合は `100vh` をフォールバックとします。`viewport-fit=cover` と `env(safe-area-inset-*)` を利用して上下・左右の予約領域を扱います。`ResizeObserver` と `resize` でキャンバスの描画サイズを追従させます。OSのセーフエリアとブラウザーツールバーの実機挙動は未検証です。

上部にHP・スコア・契約・ボスHP、中央に戦場、下部に操作デッキを配置します。戦場と操作ボタンは重なりません。チュートリアルと短い通知だけは戦場に重ねます。ボスHPの表示時には戦場領域を少し縮め、全世界が収まる等方スケーリングを再計算します。

開始時の戦場は幅720、高さ520〜1440の範囲で決まります。起動時に生成した寸法をランの途中で変えず、回転では一時停止します。再表示はレターボックスで行うため、画面回転による弾のワープ、射線の変更、オブジェクトの不可視化を避けます。

PC用の論理寸法、既存の戦闘ルール、ショートカットは維持しています。縦画面では出現位置・ボスの移動振幅を画面形状に合わせ、敵弾・プレイヤー移動の速度に0.86の係数を設けています。これは対戦バランスの人間評価を済ませたという意味ではありません。

## 残る検証

物理的なiPhone / Androidでの親指の届き方、Safari / Chromeのブラウザーバー、着信・アプリ切替、音声復帰、画面回転、長時間プレイ時の発熱を確認する必要があります。iOSネイティブアプリ、Android APK、PWAインストール、セッション復元は含みません。
